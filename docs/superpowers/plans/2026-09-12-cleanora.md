# Cleanora Implementation Plan — Master

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement phases task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Transparent native macOS cleaner — Scan → Review → Clean → Verify — full 3-phase roadmap, agent-team execution, gate per phase.

**Architecture:** SwiftUI app over a UI-free engine (`Models`/`Scanning`/`Cleaning`/`Storage`/`Support`). Stateless `Scanner` structs, `ScanCoordinator` (TaskGroup + throttled AsyncStream), `SafetyPolicy` deletion gate with write-ahead logging, JSON + UserDefaults persistence.

**Tech Stack:** Swift 6 (strict concurrency, `SWIFT_DEFAULT_ACTOR_ISOLATION=nonisolated`), SwiftUI, macOS 14.0, XcodeGen, XCTest. Non-sandboxed; App Store explicitly out of scope.

**Agent team:** `.claude/agents/{cleanora-scan-engine,cleanora-ui,cleanora-core,cleanora-reviewer,cleanora-qa}.md` — exclusive directory ownership, contracts frozen at end of Phase 0.

## Safety invariants (every one needs a named test; reviewer audits per phase)

| # | Invariant | Enforcing code | Test |
|---|---|---|---|
| I1 | No `.never` item can exist | `CleanupItem.init` precondition | `CleanupItemTests.testNeverRiskRejectedAtConstruction` |
| I2 | Item paths inside allowed roots | `SafetyPolicy.validate` | `SafetyPolicyTests.testRejectsPathOutsideAllowlist` |
| I3 | Blocked paths/fragments win over allowlist | `SafetyPolicy.validate` | `SafetyPolicyTests.testBlockedFragmentWins` |
| I4 | Unselected never deleted | `SafetyPolicy.validate` | `SafetyPolicyTests.testUnselectedRejected` |
| I5 | No confirmation → no deletion | `SafetyPolicy.validate(confirmed:)` | `SafetyPolicyTests.testMissingConfirmationRejected` |
| I6 | Destructive needs explicit confirm flag | `SafetyPolicy.validate` | `SafetyPolicyTests.testDestructiveRequiresExplicitConfirm` |
| I7 | Symlinks never followed | `DirectorySizeCalculator`, `DeletionMethodExecutor` | `DirectorySizeCalculatorTests.testSymlinkTargetUntouched` |
| I8 | Overlap dedupe, deepest path wins | `ScanCoordinator.deduplicate` | `ScanCoordinatorTests.testOverlappingScannersDeduplicate` |
| I9 | Attempt logged BEFORE deletion | `CleanupExecutor` + `CleanupLogger` | `CleanupLoggerTests.testAttemptLoggedBeforeDeletion` |
| I10 | Own logs never targets | `SafetyPolicy` blocked + logger path exclusion | `SafetyPolicyTests.testOwnLogsExcluded` |
| I11 | Failed item doesn't abort batch | `CleanupExecutor` loop | `CleanupExecutorTests.testFailureIsolatesItems` |
| I12 | Cancel leaves remaining items untouched | `CleanupExecutor` between-item checks | `CleanupExecutorTests.testCancellationBetweenItems` |

# Backlog (review findings, non-blocking)

- **Docker invariant (permanent)**: `~/Library/Containers/**` must NEVER enter the SafetyPolicy allowlist. DockerScanner's informational item is deliberately gate-rejected; the only sanctioned Docker action is `docker system prune --force` from a future UI confirm flow. Never "fix" the outsideAllowedRoots error for a Docker container path.
- **Large-files carve-out** (lead decision, Phase 2): `.largeFiles` + `.moveToTrash` + `.review` items validate anywhere under home except blocked paths/fragments/excluded roots (spec §7 "Review — user decides"). All other outside-allowlist paths stay rejected.

- **Dangling symlink** (core-b, Phase 1): a dangling symlink inside an allowed root pointing outside passes `validate` (realpath fails → link path kept). Deleting it removes only the LINK (I7 holds — target untouched), so risk is low, but the gate should either reject symlink leaves outright or force `.trashDirectory` for them. Fix in Phase 2 alongside P-01..P-07.
- **Violation ordering cosmetics**: traversal into a blocked root that's outside the allowlist reports `.outsideAllowedRoots` rather than `.blockedPath` — rejection still holds.
- **Phase 1 reviewer notes 4–9** (PASS-WITH-NOTES): Settings toggles "ask before deleting"/"auto-clean"/"confirm before cleaning" persist but are inert (confirm sheet always shows — safe direction, wire in Phase 2 U-12 pass); cancelled clean returns to stale Results (already-deleted items show old sizes; re-clean reports .alreadyGone — refresh or re-scan on return); History counts a partial item as fully removed; TOCTOU validate→delete window only closable via open-by-fd (keep on backlog); fire-and-forget ProgressHub record can land after terminal state (cosmetic row flash); CLEANORA_FIXTURE_HOME honored in release + /private/tmp hardcoded root under fixture (QA-seam hygiene); check-layering missing-dir guard is a no-op on non-git checkouts.
- **I-05 performance pass** deferred from Phase 1 gate to Phase 2 (I-04 shipped via README QA section).
- **Phase 2 reviewer notes** (PASS-WITH-NOTES, findings 1–2 fixed at abb54f6): reconciliation banner asserts causality it can't know ("already cleaned" vs "no longer present" — reword); developer-scan discoveredBytes double-counts aggregate+tool rows live (finished result honest); DeveloperCleanupViewModel isSelectable uses standardized not canonicalized path (fails closed at the gate); login toggle reads pref not live SMAppService status; auto-clean × developer-on discloses but DerivedData/CoreSimulator auto-trash deserves a clarifying Settings clause.

# Execution discipline

- Every task: failing test → fail → implement → pass → commit (`feat:`/`test:`/`fix:`).
- Agents never cross directory ownership. Contract changes route to lead only.
- Reviewer (cleanora-reviewer) audits each phase diff before gate.
- QA (cleanora-qa) runs gate procedure with fixture mode; findings go to lead.
- Gates: user approval required to start next phase.
